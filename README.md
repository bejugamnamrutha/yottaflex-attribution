# YottaFlex.ai – Marketing Attribution & ROI Analytics

A reproducible synthetic-data project for the Associate AI Forward Deployed Engineer challenge. It joins campaigns, channels, creatives, audiences, contacts, touchpoints, web sessions, leads, opportunities, orders and campaign costs; compares attribution approaches; reports ROI; and preserves labelled exceptions separately from analytical inputs.

## Stack
- Python 3.10+
- SQLite (relational persistence and foreign keys)
- Pandas (analytics)
- Streamlit (interactive demo)
- Python `random.Random` with fixed seed `20261022`

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt

# Starter dataset (quick local run)
python -m src.generator --scale starter

# Launch dashboard
streamlit run app.py

# Run tests
python -m unittest discover -s tests -v
```

## Full challenge volume

```bash
python -m src.generator --scale full --seed 20261022
```

Full scale uses 500 campaigns, 50,000 contacts, 200,000 touchpoints and 10,000 opportunities. Starter scale uses the same generator and schema with smaller configurable counts. Edit `config.json` to change either scale.

## Outputs

The `data/` directory is generated by the command above:
- One CSV per entity/table.
- `attribution.db`: SQLite database with primary/foreign keys and indexes.
- `AttributionResult.csv`: model credits and revenue.
- `ground_truth.json`: labelled edge cases and expected decisions; keep separate from model input features.
- `manifest.json`: seed, counts, generation timestamp and SHA-256 checksums.
- `validation_summary.json`: integrity and reconciliation checks.

Do not commit generated full-scale data unless the repository size is acceptable. Commit source, docs, tests, config and optionally a small starter sample.

## Attribution definitions

All eligible touchpoints must belong to the opportunity's contact and occur at or before its closed-won timestamp. Post-conversion touches are excluded.

- **First-touch:** 100% credit to the earliest eligible campaign.
- **Last-touch:** 100% credit to the latest eligible campaign.
- **Linear:** equal credit across distinct campaigns in the journey.
- **Position-based:** 40% to first, 40% to last, and 20% split evenly among middle campaigns. With one campaign, it receives 100%; with two, each receives 50%.

Each opportunity/model's credits sum to 1. Revenue is deduplicated by `external_order_ref` and only USD orders without an issue label are included in the analytical revenue. Cost currency mismatches and labelled cost omissions are excluded from USD ROI until corrected with an approved FX rate or source correction.

ROI = (Attributed Revenue - Campaign Spend) / Campaign Spend.  
ROAS = Attributed Revenue / Campaign Spend.

Campaign spend is the sum of valid USD `CostRecord` rows. Campaign budget is a planning limit, not spend.

## Data model and cardinality

- Channel 1:N Campaign.
- Campaign 1:N Creative; Campaign N:M Audience through `CampaignAudience`.
- Contact 1:N Touchpoint, WebSession, Lead and Opportunity.
- WebSession 1:N Lead (optional session on a lead).
- Lead 1:N Opportunity (the generated baseline uses one lead per opportunity).
- Opportunity 1:N Order (revenue facts).
- Campaign 1:N CostRecord and AttributionResult.
- Opportunity 1:N AttributionResult (one or more campaign credits per attribution model).
- EventHistory stores append-only lifecycle events.

All generated IDs are stable, zero-padded and immutable within a seed/run. Dates are UTC ISO-8601. Effective campaign dates are `start_date` and `end_date`; lifecycle status is stored explicitly.

## Data dictionary (summary)

| Entity | Primary key | Important fields / validation |
|---|---|---|
| Campaign | campaign_id | channel_id FK, dates, nonnegative budget, currency, status |
| Channel | channel_id | unique name |
| Creative | creative_id | campaign_id FK, creative_type enum |
| Audience | audience_id | audience_type enum |
| Contact | contact_id | created_at, region, consent_status |
| Touchpoint | touchpoint_id | contact/campaign/channel/creative/audience FKs, occurred_at, touch_type, offline flag |
| WebSession | session_id | optional contact FK, started_at, identity evidence |
| Lead | lead_id | optional contact/session FKs, created_at, status |
| Opportunity | opportunity_id | lead/contact FKs, created/closed dates, stage, expected_value, currency |
| Order | order_id | opportunity FK, order date, revenue >= 0, currency, external_order_ref |
| CostRecord | cost_id | campaign FK, incurred_at, amount >= 0, currency, cost_type |
| AttributionResult | result_id | opportunity/campaign FKs, model enum, credit in [0,1], attributed revenue |

The SQL schema in `src/generator.py` is authoritative. The generated CSVs contain the actual fields. All relationships use explicit foreign keys, with intentional optional identity links represented as empty/null values.

## Exception scenarios

1. Duplicate revenue: second order row repeats `external_order_ref`; deduplicate before revenue aggregation.
2. Post-conversion touch: labelled touchpoint occurs after close; exclude from attribution.
3. Currency mismatch: EUR cost in a USD analysis; flag and exclude rather than silently convert.
4. Omitted cost: one campaign has no cost record; surface missing-cost flag.
5. Anonymous session: no contact identifier or identity evidence; preserve unresolved identity and do not infer a person.

`ground_truth.json` is for evaluation only. Do not use it as a feature or merge it into model input data.

## Reproducibility

Run twice with the same seed and config. Compare CSV checksums in `manifest.json`. Generation timestamps and database bytes can vary due to runtime metadata; compare entity CSV checksums/counts for deterministic evidence. The random data generation is seeded; attribution calculation is deterministic.

## Validation

The generator checks:
- Foreign-key integrity.
- Primary-key uniqueness for core entities.
- Touchpoint campaign references.
- Closed-won opportunities with orders.
- Per-opportunity/per-model attribution credit sums.
- Ground-truth case count.

Run the tests with `python -m unittest discover -s tests -v`.

## Design decisions and limitations to discuss

- This is synthetic data only; no personal or confidential customer data is used.
- The current generator uses USD as the baseline currency and deliberately inserts an EUR exception. Production-grade FX handling requires a dated, approved exchange-rate table and explicit conversion policy.
- Attribution is deterministic and rule-based, not a causal-incrementality model. It describes credit allocation, not proof that a campaign caused the sale.
- Contact identity is synthetic. Anonymous identity is never inferred without evidence.
- For a production extension, add consent-aware retention, campaign-level effective-dated channel mappings, late-arriving event handling, idempotent ingestion, role-based access, and a formal data-quality quarantine.
